# 前端重构高风险契约（Phase 1 / Phase 2 通用）

> 状态：2026-10-28 复核，Phase 1 已抽出 14 个组件；以下机制**目前未改动**，Phase 2 改样式前必须逐条对照。
> 原则：这些不是「代码风格问题」，而是**依赖运行时行为 / DOM 结构 / 类名 / 调用时序**的隐性契约，改动即回归。

## 1. `flushSync`：21 处，不能删、不能挪

统计：`grep -c flushSync webapp/src/App.svelte` = 21（含 import 1 处，实际调用 20 处）。

原因：Svelte 5 在 `await` 之后对 `$state` 赋值不会立即驱动条件渲染/组件挂载；项目里凡是「await 后马上要读新 DOM 或让新 UI 出现」的地方都用 `flushSync(() => {...})` 强制同步刷新。删掉后表现不是报错，而是 **UI 冻结 / 弹窗不出 / 滚动失效**。

位置分布（当前行号）：

| 行 | 场景 |
|---|---|
| 238 / 249 / 261 | 连接账号流程（状态切换后立即读 UI） |
| 351 | 任务提交后刷新状态 |
| 627–670（3 处） | **手机号登录状态机**：切步骤、显示验证码输入、进入下一步 |
| 1016 | 会话/消息相关状态 |
| 1647 / 1658 | 右键菜单打开/关闭（之后查询 `.ctx`） |
| 1740 / 1760 | WebSocket 收到消息后插入聊天 |
| 1864 / 1878 / 1881 | 启动时恢复状态、同步 `details` 展开状态 |

规则：
- 不得删除、合并、改成 `tick()`，也不得把赋值移到 `flushSync` 外面；
- 若把相关逻辑搬进子组件，`flushSync` 的调用点与先后顺序必须原样保留；
- 改样式（尤其 `display` / 条件渲染结构）时，先确认没有依赖 flushSync 后才能拿到的 DOM。

## 2. 分组拖拽：约 90 行，命中检测依赖几何尺寸

位置：`onGroupMouseDown`（1527 起）+ `onWinMouseMove` / `onWinMouseUp` + `dragGroup` / `dragGroupOver` 状态。

机制：按下分组按钮后挂全局 `mousemove` / `mouseup`，用鼠标坐标与按钮矩形做命中判断，并带「防抖点击」（拖动阈值内视为点击）。**按钮的 padding、高度、间距参与命中计算**。

规则：
- 不改分组按钮（`.grp`）的 padding / 高度 / 外边距 / 圆角尺寸；
- 不移除按钮上的 `onmousedown`，不改变事件绑定元素；
- 如必须调整视觉尺寸，需同步修改命中阈值并人工验证拖拽排序 + 单击切换两个行为。

## 3. DOM 直接查询：5 处，类名与元素层级是契约

| 行 | 选择器 | 所在组件 | 用途 |
|---|---|---|---|
| 224 | `.log` | `LogView.svelte`（`<ul class="log">`） | 日志自动滚到底 |
| 1024 | `.log` | 同上 | 打开日志视图后滚到底 |
| 1155 | `.chat-history` | `ChatView.svelte`（`<ul class="chat-history">`） | 聊天滚到底 |
| 1651 | `.ctx` | `ContextMenu.svelte`（根 `<div class="ctx">`） | 判断点击是否落在菜单内 |
| 1882 | `details.card` | `FunctionCards.svelte` | 恢复折叠状态时逐个设置 `open` |

规则：
- 这些 class 名、元素标签、层级不能改；组件根节点不能换成别的标签；
- 不要让这些元素被 `display:none` / 条件渲染包裹到查询时机之外（例如给 `.log` 外层加 `{#if}` 会直接失效）；
- 若引入 CSS Modules / 哈希类名方案，必须给这些节点保留稳定的全局类名。

## 4. 手机号登录状态机：3 处 flushSync

位置：627–670，覆盖「输入手机号 → 发送验证码 → 输入验证码 → 完成」的步骤切换。

规则：
- 步骤切换依赖 flushSync 让下一步的输入框/按钮立即出现，不能改成 `$effect` 或异步渲染；
- 输入框的 `bind:value` 不能改成手动 `oninput`（中文/粘贴输入行为会变）；
- 回归方式：真实账号走一遍「手机号登录」，观察每一步是否卡住。
