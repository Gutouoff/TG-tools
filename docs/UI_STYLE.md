# 界面用语与代码注释规范

> 适用范围：Web 前端（`webapp/src`）、后端返回给界面的提示（`server.py`）、CLI 文本（`tg_tool.py` 的 `DEFAULT_TEXTS` + `界面文本.txt`）。
> 原则：同一概念只用一个词；能一句话说清就不写两句；不把给开发者看的说明写进界面。

## 一、术语表（固定用法）

| 概念 | 固定用词 | 不要用 |
|---|---|---|
| 被管理的 Telegram 账号 | **账号** | 帐号、号、小号（仅产品名「小号工具箱」保留） |
| 聊天列表里的一项 | **会话** | 对话、聊天记录 |
| 批量删除任务 | **删对话**（功能名，保留） | 删除会话、清理对话 |
| 一对一聊天 | **私聊** | 单聊、私人聊天 |
| 多人群 | **群组** | 群、群聊 |
| 广播频道 | **频道** | 通道、channel |
| Bot | **机器人** | bot、Bot（句首除外） |
| Telegram Desktop | **客户端** | Telegram、TG 客户端 |
| 本工具 | **程序** | 软件、应用、工具（指本程序时） |
| 建立 Telethon 连接 | **连接** | 登录（登录只指验证码/二维码/2FA/邮箱验证流程） |
| 修改账号文件夹名 | **重命名** | 改名 |
| 弹出的小窗口 | **弹窗** | 对话框、窗口 |
| 受保护名单 | **白名单** | 白名单列表、保护名单 |

## 二、句式

- 按钮、菜单、标签：动词或名词短语，**不加句号**，不加「请」。例：「连接」「删除账号」「刷新」。
- 状态：`已连接` / `连接中…` / `未连接` / `监听中` / `已停止`。
- 成功提示：`已 + 动词 + 对象`。例：「已复制 3 条日志」「已重命名」。
- 失败提示：`<操作>失败：<原因>`，原因尽量给下一步。例：「连接失败：验证码错误，请重新获取」。
- 空状态：`暂无…` / `请先…`。例：「暂无会话」「请先连接账号」。
- 二次确认：`确定要…吗？`，危险操作补一句后果。

## 三、标点与格式

- 中文文案统一全角标点：`，。：；！？（）「」`。
- 省略号用 `…`，不用 `...`。
- 数字、英文、路径前后不加空格（项目既有习惯）。
- 路径、账号名、命令原样书写，不加引号；需要强调时用「」。
- 单位与数字之间不加空格：`1.2.3`、`300s`、`3 天`。

## 四、日志

- 文件格式：`YYYY-MM-DD HH:MM:SS [LEVEL] 内容`，由 `tg_log` 统一生成，不手写时间戳。
- 面向用户的日志同样遵守上面的术语和标点；错误必须带原因。
- 不把 token、手机号、密码写进日志（手机号由 `tg_log` 自动打码）。

## 五、代码注释

- 只写「为什么」和约束，不复述代码在做什么。
- 成句的注释放在被说明代码的**上方**；行尾只允许极短的字段说明（≤ 15 字），`# noqa`、`# type: ignore` 这类工具指令除外。
- 新写的注释用全角标点；历史注释不做批量替换（注释里的代码示例、路径、参数一旦改坏得不偿失）。
- 不用口语、感叹号、表情；不写「注意」「记得」「千万别」这类提醒式措辞。
- 函数/类的 docstring 说明输入、副作用和线程约束；模块顶部说明职责边界。
- 临时方案必须写明原因和移除条件，不写「临时」「先这样」。

## 六、新增文案的落点

- 前端：直接写在 `App.svelte` 对应位置，保持本规范。
- 后端返回给界面的 `msg`：本规范同样适用。
- CLI：`tg_tool.py` 的 `DEFAULT_TEXTS` 加 `t0xx` key，并同步仓库根目录 `界面文本.txt`（运行目录那份才是活的）。
